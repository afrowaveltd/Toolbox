# Virtual Markdown stress test

## Design

VirtualMarkdownReader stores a small catalog of prepared Markdown templates.
It selects them using an explicitly seeded xorshift32 sequence and yields
characters through TextReader.ReadAsync(Memory<char>). Generated UTF-8 bytes
are counted at completed block boundaries. The last template finishes even if
the requested minimum size was already crossed.

## Assertions

- All input reaches the real ExchangeHouse MarkdownStreamingReader scanner.
- Every line has a contiguous 64-bit UTF-16 source offset.
- Observed UTF-8 byte count equals generated byte count.
- Fence opening and closing counts match in the generated corpus.
- Optionally every line passes to production MarkdownSpectreRenderer, with
  output discarded via TextWriter.Null rather than captured in RAM.
- Elapsed time, sampled managed heap and RSS are reported.
- Managed heap sampled over --max-heap-mib growth fails; this is not an exact
  peak measurement nor an OS-enforced allocation limit.

The generator covers headings, quotes, nested lists, Markdown-like code text,
fenced Bash/C#, Unicode, links, images and long bounded lines.

## Adversarial unit tests

A separate virtual reader generates a single open code fence with 50,000
code lines, no large in-memory string. Other tests cover single-character
reads, mixed CR/LF/CRLF boundaries, quote-owned fence interruption, list
metadata, cancellation, empty input and oversized individual lines.

## Limits and next work

The scanner indexes open structures without retaining body content. It is not
a complete incremental CommonMark AST, and the Showcase full-file viewer
still uses complete-document parsing. Test actual OS-level memory limits and
Windows/Debian real-terminal appearance separately. Future work should handle
multiline list ownership, deferred link references and interactive paging.
